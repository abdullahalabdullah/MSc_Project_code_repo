# =============================================================================
# SEPARATE venv for NEWER local monitor models (config monitor.local.models
# entries like gemma_e4b) that the main pinned env cannot load.
#
# Why a second env: the main requirements.txt pins vllm==0.8.5 +
# transformers==4.51.3 — the known-good pairing for the Qwen3 inference
# pipeline on a CUDA-12.8 driver, and NOT upgradable in place (newer
# transformers breaks vLLM 0.8.5's tokenizer API; see requirements.txt
# header). google/gemma-4-E4B-it is newer than that stack: its
# tokenizer_config uses an extra_special_tokens format transformers 4.51.3
# cannot parse (AttributeError: 'list' object has no attribute 'keys') and
# vLLM 0.8.5 does not know the architecture.
#
# Usage (fresh venv; needs ~10 GB disk for the torch stack + the Gemma
# weights in the HF cache):
#
#   python -m venv ~/gemma_mon_env
#   source ~/gemma_mon_env/bin/activate
#   pip install -r requirements-gemma-monitor.txt
#   bash monitorability-eval/run_local_monitor.sh <model> --dataset ... \
#        --hint professor --monitor gemma_e4b
#
# ONLY step 3 (--backend local, non-Qwen monitors) runs from this env.
# Inference (step 2) and the qwen3_8b monitor keep using the main env.
#
# Troubleshooting:
#   * "The NVIDIA driver on your system is too old": the newest vLLM bundled a
#     torch built for a newer CUDA than the pod's driver. Step down, e.g.
#     pip install "vllm==0.9.2" (torch 2.7, runs on 12.6+ drivers) — but a
#     brand-new model family may need the newest vLLM, in which case pick a
#     pod image/driver that matches instead.
#   * Same tokenizer AttributeError as before: transformers resolved too old —
#     run `pip install -U transformers` inside this venv.
# =============================================================================

# Newest vLLM — new model architectures (Gemma 4 family) need it. Brings its
# own matched torch; floors below only guard against a stale resolve.
vllm>=0.10
transformers>=4.55

# step-3 script deps (src.gmean2_metrics imports numpy at module level;
# yaml/tqdm for config + progress display)
numpy>=1.24.0
pyyaml>=6.0
