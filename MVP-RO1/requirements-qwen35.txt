# =============================================================================
# Qwen3.5-4B environment for MVP-RO1.   *** SEPARATE from requirements-qwen.txt ***
#
# requirements-qwen.txt (vLLM 0.8.5 / transformers 4.51.3) runs the Qwen3 family
# (model_type "qwen3"). It does NOT run Qwen3.5 — that checkpoint reports
# model_type "qwen3_5" and fails on 4.51.3 with:
#   ValueError: ... model type `qwen3_5` but Transformers does not recognize ...
# (exactly the error seen for Qwen/Qwen3.5-4B on the 4.46.3/0.6.3 base stack).
#
# WHY A THIRD ENV
# Qwen3.5 is a *natively multimodal* model — "Causal LM with Vision Encoder",
# image-text-to-text, built on the hybrid GDN (Gated DeltaNet) attention stack.
# Its architecture (`Qwen3_5...`) was only contributed to transformers on
# 2026-02-09, so it needs:
#     transformers >= 5.2.0           (qwen3_5 architecture)
#     vLLM        >= 0.17.0           (GDN support; model card says "main branch")
# Both are far newer than the Qwen3 pins and pull a newer torch — INCOMPATIBLE
# with both the Llama/Tulu env and the Qwen3 env. Install in its OWN fresh venv.
#
#   python -m venv ~/qwen35_env
#   source ~/qwen35_env/bin/activate
#   # see "INSTALL" below — do NOT just `pip install -r` this file blindly,
#   # the torch/CUDA pairing has to be forced for an older driver.
#
# Only scripts/02_run_inference_qwen.py (with --config-block qwen35_inference)
# and 07_estimate_accuracy_qwen.py load the model and need this env. Steps 03-06
# are model-agnostic and run under any environment.
#
# -----------------------------------------------------------------------------
# *** CUDA-DRIVER CONSTRAINT (the hard part) — confirmed: this box is <= 12.8 ***
#
# vLLM 0.17+ defaults to a torch built for CUDA 12.9+. On a 12.8 (or lower)
# driver that torch will NOT load:
#   RuntimeError: The NVIDIA driver on your system is too old ...
# (same failure class documented in requirements-qwen.txt for newer vLLM.)
#
# FIX: force a torch wheel whose CUDA build runs on a 12.8 driver. torch built
# for cu124 / cu126 / cu128 all run on a 12.8 driver; cu129+ does NOT. Use uv's
# --torch-backend, which reinstalls torch with the matching CUDA suffix AFTER
# vLLM is resolved (the documented vLLM install path for Qwen3.5):
#
#   pip install uv
#   uv pip install -U vllm --torch-backend=cu128     # or =auto to autodetect
#   uv pip install "transformers>=5.2.0"             # qwen3_5 arch
#   uv pip install -r requirements-qwen35.txt        # the rest (no torch/vllm)
#   # verify the torch CUDA build matches the driver BEFORE downloading 8GB weights:
#   python -c "import torch,vllm,transformers as t; \
#              print('torch', torch.__version__, 'cuda_ok', torch.cuda.is_available()); \
#              print('vllm', vllm.__version__, 'transformers', t.__version__)"
#
# If vLLM 0.17.0 still cannot build the GDN kernels, the model card calls for
# vLLM *from main* — last resort, much slower to install:
#   uv pip install "git+https://github.com/vllm-project/vllm.git" --torch-backend=cu128
#
# Always install into a FRESH venv (~10-12 GB free). Downgrading/upgrading an
# existing env in place leaves mismatched torch/transformers/flashinfer leftovers
# that surface one error at a time. Do NOT install flashinfer here.
#
# -----------------------------------------------------------------------------
# *** UNVERIFIED — these pins are NOT a known-good pairing like requirements-qwen.txt ***
# requirements-qwen.txt lists EXACT, tested pins. This file cannot: Qwen3.5
# needs releases newer than were verifiable when it was written, and the model
# card itself points at main-branch vLLM. Treat the versions below as FLOORS,
# run the verify line above, and pin whatever combination actually loads.
# =============================================================================
